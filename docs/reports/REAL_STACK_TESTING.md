# Disposable real-stack testing

Run `python scripts/run_fullstack_tests.py` from a development checkout after installing the repository Python development dependencies and frozen pnpm dependencies. Supply `--pnpm`, `--tusd`, and `--caddy` with absolute executable paths when those programs are not on PATH. The supported test service versions are tusd 2.9.2 and Caddy 2.11.4, matching the repository deployment versions. Python requires working libvips; install the Playwright Chromium runtime with `pnpm --dir apps/web exec playwright install chromium`.

The launcher creates a disposable SQLite database, upgrades all migrations, creates a random fixture administrator and admitted synthetic OME-TIFF, builds the web application, and starts loopback API, conversion worker, tusd, tile service, frontend, and Caddy processes. It reuses the production Caddy authorization, headers, and static tile handlers. It discards inherited PathLab targets, credentials, and feature settings and starts backend processes outside the checkout so a local `.env` cannot select production. It does not accept an external application target.

The imaging journey uses visible Library navigation and actual API responses. It interrupts a later resumable-upload request after some bytes were accepted, verifies retry at a positive offset, waits for actual conversion, opens a private preview, saves an annotation and reloads it, signs in from a private link in a new browser context, publishes through the deidentification dialog, decodes an anonymous DZI tile, and revokes both metadata and new tile access. Network fault injection aborts one request; it does not replace backend responses or inject application state.

Owned services and fixture storage are cleaned up after the run. Temporary administrator credentials are not recorded in Playwright traces, screenshots, or videos. A failed run emits bounded synthetic service diagnostics with generated secrets redacted. Forced host termination still requires operator verification of process cleanup.

The same journey creates a class folder through the Library, moves the published slide, finds the folder in Classroom, prepares and starts a class, admits one learner through the visible invitation, recovers the teacher in a fresh tab using server state, reloads the learner, finishes the class, and revokes review access. Separate real-edge tests reject internal URLs and oversized JSON and prove forged forwarding headers cannot evade login admission.

The `fullstack` CI job runs these journeys independently from the responsive browser matrix. The existing PostgreSQL CI job additionally runs shared-admission tests. A passing SQLite journey with one learner does not establish PostgreSQL behavior, classroom/media capacity, complete security, accessibility, Assessment, or the Golden Institution Journey. Those require their own current evidence. Production activation and qualification remain separate from these checks.
