# Separate operational queue and application protocol

Status: source preparation only. No service, registration job or browser measurement has run under this protocol.

`real-api-nine-serial-operational-jobs/1` measures nine actual `align_benchmark` API requests in one owned disposable loopback service lifetime. Before any operational run, the root selected published public pair index 10: the original whole-section Rat-Kidney H&E 1164×787 and PanCytokeratin 1123×724 JPEGs. This avoids the known mismatch between tight CIMA tissue crops and the API's configured defaults, which do not supply the scientific cohort's explicit cropped-input flags. Their exact encoded bytes remain unchanged; no physical calibration is supplied. The fixture may create a complete pyramid, whose full-resolution tile is the original JPEG and whose lower levels are derived solely for viewing. Source/frame/pyramid hashes and settings are captured before admission. This is an operational profile of API-configured defaults, separate from the scientific frozen crop/settings campaign. No anatomical accuracy or qualification follows from it.

The nine recipes are Native overview, VALIS, wsireg, HISAlign, DeeperHistReg classical and learned, Native→wsireg, VALIS rigid→wsireg, and Native→VALIS. Each POST requests exactly one recipe with rerun enabled. The next request waits for the preceding real job to be terminal. The existing worker enforces the 600-second/7-GiB registration boundary. Its API CPU-thread declaration remains two; OMP, MKL, OpenBLAS, NumExpr and ITK environment limits are one. Each request has a 660-second observation ceiling, including waiting. A job still active or quarantined at that ceiling stops the profile and requires cleanup/reconciliation; it does not authorize another request. One service lifetime has a separate maximum of 7,800 seconds including startup, queue observation, four-browser applications and cleanup. Existing 1,200-second acceptance journeys are unchanged.

The owned research stack explicitly enables the four optional-engine flags and admits the four local weights by path and SHA256. VALIS uses the existing `PATHLAB_ALIGNMENT_VALIS_DISK_WEIGHTS_PATH`/`_SHA256` and `PATHLAB_ALIGNMENT_VALIS_LIGHTGLUE_WEIGHTS_PATH`/`_SHA256` fields. Learned DeeperHistReg uses `PATHLAB_ALIGNMENT_DEEPERHISTREG_SUPERPOINT_WEIGHTS_PATH`/`_SHA256` and `PATHLAB_ALIGNMENT_DEEPERHISTREG_SUPERGLUE_WEIGHTS_PATH`/`_SHA256`. The latter four optional fields default to null, and providing resources does not enable the engine flag. The real API previously had no way to receive its already-required learned resources; a focused endpoint test reproduced a 409 refusal despite valid declared resources, then verified 202 admission after the configuration mapping repair. Missing files, bad hashes and changed bytes remain fail-closed. Resource paths are private in stored settings and are projected out of candidate and active-map responses; hashes remain visible. This configuration does not bundle research resources into production images or alter optimizer settings. The source/resource/license ledger and actual common runtime are bound separately before execution.

The Python controller starts no services and opens the disposable database read-only. It records request-to-ack elapsed time, actual job creation/checkpoint/resource declarations, last queued observation before the first running/checkpointing/terminal observation, terminal observation and candidate-fetch elapsed time. Later preemption/requeue cannot overwrite the original queue interval. Since the schema has no immutable job-start timestamp, queue time is an interval with its observation timestamps. If polling first sees a terminal job, the interval is explicitly loose and does not establish execution time. `queueSeconds` stays null. Worker runtime/preparation values remain their original labeled checkpoint/evidence values; observation, request, queue and engine times are not interchangeable.

Every recipe remains in the nine-row denominator. API refusal has no invented job or application time. Rejected, unavailable, missing and invalid candidates remain failures or unmeasured application rows. Partial request receipts are persisted before POST; an interrupted request cannot automatically requeue, because its acknowledgement may have been lost. Resume skips completed, admission-bound rows. Interrupted rows require explicit read-only reconciliation to the existing job. Fatal containment or a nonterminal observation ceiling stops progression. Private authentication contains only the disposable cookie and CSRF header and is never recorded in receipts.

After all nine jobs are terminal, the UI harness may serially open Chromium, Firefox, WebKit and mobile Chromium against the same service lifetime. For each current eligible candidate it measures Preview click to first valid actual OpenSeadragon event/render-readback interval, records source/candidate/map/snapshot digests, and checks supported-cell centroids with an independent geometric oracle. This includes the UI observation interval; a map-setter event measures only its narrower setter scope. Failed or unsupported application is null with its failure category. This does not supply cold or warm model timing, anatomical agreement, or the scientific campaign's viewport timings. The UI owner controls these source files and their separate conformance checks.

Automated regional correction records scripted one/two-point action counts and observed Preview/Cancel durations. It avoids Save while candidate applications are pending, preserving comparison version and canonical maps. These are automation interaction measurements. Actual human correction duration, human effort and anatomical correction accuracy remain null without an independently reviewed human observation.

`scripts/measure_alignment_operational_profile.py` requires the disposable API origin, existing SQLite database, comparison set/version, a private launcher guard and auth-header file, and an explicitly admitted private output directory. The guard binds source proof, configuration/resource proof and service ownership proof. It rejects the original ports 8001/5175, redirects and linked database/output paths. `operational-queue.json` and per-recipe receipts contain private candidate maps; public projection must whitelist numeric timings, recipe ordinals, bounded statuses and digests and omit coordinates, identities, paths and authentication. The service wrapper owns startup, PID/start-identity proof, final cleanup and preservation of the original services. Queue profiling and the warm registration campaign run serially, never concurrently.

No launch is authorized by this document. Actual execution follows the root's final source review, full backend and acceptance terminal checks, runtime/resource admission and explicit scheduling release.
