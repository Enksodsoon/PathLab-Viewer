# Bound backup lifecycle and recovery horizons

Zero-Cash Production will continuously receive WAL, complete daily PostgreSQL block-incremental backups no more than 26 hours apart, complete full backups no more than 168 hours apart with qualified scheduling margin, protect each admitted immutable object before authority, and reconcile the complete object inventory nightly. The continuous WAL pool retains at least the rolling seven-day PITR window plus the maximum 26-hour daily-anchor interval and deletes every segment by age nine days, while each older discrete anchor carries only its own consistency WAL; dependency-aware chains preserve at least 28 days of discrete restore anchors and every Backup Generation still expires before age 35 days. Logical expiry begins on day 34 and completes deletion, prune, verification, and a signed Deletion Receipt before day 35; each disconnected generation also uses a random, non-derivable per-rotation epoch DEK whose independently held recovery shares are automatically crypto-erased with signed quorum evidence before that deadline.
