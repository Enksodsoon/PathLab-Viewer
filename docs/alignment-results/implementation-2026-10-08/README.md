# Alignment implementation and measured limits - 2026-10-08

The implemented workflow is **Slides -> Sync -> Adjust region**. Original image pixels remain in two panes by default, up to four selected panes. Approximate supported overview alignment initializes navigation while refinement proceeds. Engine controls and legacy three-point correction stay in Advanced; no Fast or Accurate preset is qualified. This report consolidates actual source-bound engineering and development observations. It does not claim production deployment, anatomical qualification or completion of pending gates.

One point adjusts offset using the currently supported regional/local/overview linear basis; two points adjust rotation and scale. Preview/Cancel/Save/Reload retain navigation and canonical maps. Corrections are separate immutable regional revisions. Source/frame/calibration snapshots, comparison CAS and one-point basis tokens reject stale saves; later canonical replacement does not invalidate a saved region solely by changing its fitting basis. Candidate Preview requires affirmative current pair, graph and eligibility/snapshot proof.

Reproduced repairs cover hidden references, refinement/correction races, anchor cycles, null-SHA and source/frame changes, actual sampling geometry, empty DZI fallback, rotated viewport bounds and current rotation. Support permits bounded enclosed holes under the unchanged automatic foreground predicate, while preserving glass and fragment gaps.
