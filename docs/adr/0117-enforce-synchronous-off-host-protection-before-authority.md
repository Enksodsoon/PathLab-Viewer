# Enforce synchronous off-host protection before authority

Zero-Cash Production will acknowledge an authoritative PostgreSQL write only after Barman 3.19.1, using matching PostgreSQL 18 client tools and `pg_receivewal --synchronous`, has synchronously flushed its WAL off-host; `synchronous_commit=on`, `fsync=on`, `full_page_writes=on`, the named receiver, and lossless storage-flush behavior are frozen qualification inputs, and a pinned server-side pre-commit guard rejects authoritative transactions whose session attempts to weaken that boundary. Loss of durable acknowledgement stops authoritative writes while preserving safe reads. A new immutable object remains `PENDING_PROTECTION` until a Backup Target worker running restic 0.19.1 has used a signed, hash-addressed, short-lived pull grant to fetch and verify it, committed the snapshot through rest-server 0.14.0, and returned a valid Protection Receipt; production holds no restic repository decryption, append, delete, prune, unlock, or administration credential, choosing bounded data loss over write availability without creating an uptime or RTO promise.
